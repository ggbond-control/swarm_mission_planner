# Swarm 任务规划

`swarm_mission_planner` 在架构职责上接替 `capability_mission_planner`，当前实现是独立开发的简化规划器，**尚不是旧版完整功能和性能的替代品**。不导入、链接或调用旧规划包，也不维护 Leader、执行权限或任务终态。

## 接口与代码职责

节点入口 `swarm_mission_planner_node`；请求／结果为 `/swarm/planner/request`、`/swarm/planner/result`（标准 String JSON）。离线入口 `swarm_plan` 接受包含 mission、mission_id、robots 的 JSON 文件。

| 文件 | 职责 |
| --- | --- |
| `maps.py` | 地图解析、原点旋转、障碍净空、跨图通道及栅格搜索 |
| `planner.py` | 能力筛选、任务分配、检查点、保守路线依赖 |
| `worker.py` | 可回收的独立计算进程、超时和资源诊断 |
| `node.py` | ROS 请求和结果适配，不直接进行 CPU 搜索 |
| `cli.py` | 离线 JSON 输入／输出 |

节点不自动生成 runtime 或 reports；结果由协调器持久化。`footprint_radius` 和 `free_thresh` 须与协调器预检一致。`planning_timeout` 默认 45 秒，应小于协调器的规划期限（默认 60 秒），为消息和提交留余量。

## 与旧规划器的差异

| 项目 | 原 C++ 规划器 | 当前新实现 |
| --- | --- | --- |
| 语言／工程范围 | C++ 库、ROS 服务、离线适配与图形输出 | Python 库、ROS 节点、独立计算子进程 |
| 路径搜索 | A*、跨图稀疏搜索、地图缓存和代价等 | 栅格 Dijkstra、显式通道；每个候选独立搜索，无持久地图缓存 |
| 分配 | 插入、任务搬移、有限点数均衡与优化预算 | 高优先排序、按能力和预计负载贪心追加 |
| 多机协调 | 安全时间区间、资源预约、局部修复与 CBS 回退 | 单图保守串行依赖，按前序真实路线结束解锁 |
| 跨图多机碰撞 | ROOT 空间处理与相应协调 | 未实现完整 ROOT 冲突校验；多设备涉及多个地图时明确拒绝 |
| 单设备跨图 | 支持 | 支持显式通道和已知平移关系 |
| 机器人差异 | 可配置逐机净空／footprint 等 | 速度、能力不同；净空半径为统一参数 |
| 其他约束 | 返航、任务位置容差、通道能力／耗时等 | 未实现对应完整语义 |
| 输出 | plan、文本、路线 PNG、可选 GIF 等 | JSON 路线、task／turn 检查点和依赖；Agent 可执行 holding，但当前算法不生成时间预约等待策略 |

代码更少的主要原因是算法和业务范围缩小，并移除了 C++ 类型声明和较多输出设施；不能解释为仅换用 Python 就获得相同功能。现有实现保留挂载操作、能力匹配、非法起点汇总和原始任务 ID；不自动修正起点，不承诺最优分配。

多图目录不代表能够跨图执行所有多机任务。只有单图内可检查的多机计划或单设备跨图计划可使用当前实现；其余情况失败返回，不输出未经验证的安全计划。

## 性能与超时边界

这里是任务级规划，不是底层实时运动控制，但规划耗时仍必须受限。NumPy／SciPy 的部分地图处理在编译扩展中运行；Dijkstra、候选遍历和路线协调仍有 Python 循环。CPU、地图面积、可达区域、任务点数及能力候选数都会影响耗时，目前没有开发板性能保证。

ROS 节点和基准工具使用 spawn 子进程，避免与 ROS 回调争用同一 Python GIL；超时覆盖子进程启动、地图载入和完整计算。超时后回收进程再受理下一次请求，重复 request_id 不重复计算，新 request_id 可替代旧计算。结果诊断提供 `compute_seconds` 和 Linux `peak_rss_kib`，不改变计划摘要。直接调用库函数或离线 `swarm_plan` 仍是同步计算，不具有父进程的整次超时回收机制。

这些措施限制资源占用并保持控制适配响应，不保证一定在期限内找到计划；操作系统卡顿、内存压力也不是硬实时保障。搜索预算用尽单独报告，不能误写成任务点物理不可达。

进入实机替代前，需要在目标板、代表性真实地图和典型／上限任务量上验证耗时分布、峰值内存、失败率、规划质量及对导航的影响。若 Python 搜索无法满足预算，建议在本包内部独立建设 C++ 搜索／协调核心，保留现有进程和协议边界；不通过调用旧包绕过架构约定。实现语言不应因架构变为分布式就被强制改为 Python。

构建和全套启动见 [协调器 README](../swarm_mission_coordinator/README.md)；本地合成基准、命令与验证范围见 [TEST_LOG](TEST_LOG.md)。
